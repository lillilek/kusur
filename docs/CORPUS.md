# Кусурский корпус

Это комплект настоящего **Tsakorpus**. GitHub Pages содержит страницу `corpus.html`; Python-приложение и Elasticsearch запускаются отдельно. Пока сервера нет, страница показывает статус подготовки без кнопки поиска.

## Первая версия

Текст `kus_2026_zuhr_1962_text_Kistaman_2`, GUID `a01bc385-db60-4255-a01d-9611a82108ae`: 4 сегмента, 4 русских перевода, 68 слов, 50 слов с морфемным разбором, 108 морфем, 105 глосс. Текущая сводка: `data/corpus-status.json`.

- `tsakorpus/corpus/kusur/*.json` — документы Tsakorpus.
- `tsakorpus/conf/` — параметры и пометы.
- `tsakorpus/reports/` — отчёты качества.
- `tools/import_flex.py` — импорт XML, Python 3.10+ без дополнительных библиотек.
- `deploy/` — сборка сервера, HTTPS, проверка индекса.
- `.private/` — локальные оригиналы, примечания и резервные копии. Исключена из Git и Docker; резервируйте отдельно.

## Обновление текстов в Windows

1. Получите актуальную копию репозитория (Fetch/Pull в GitHub Desktop).
2. FieldWorks → Texts & Words → Interlinear Texts → Analyze. Включите строки слов, морфем, Lex. Entries, Lex. Gloss, частей речи и русского перевода.
3. File → Export Interlinear → Verifiable generic XML. Выгрузите актуальные тексты.
4. Дважды нажмите `UPDATE-CORPUS.cmd`. Выберите XML. Нужен Python с Tkinter (обычный установщик Python для Windows).
5. Проверьте `tsakorpus/reports`. Предупреждения о неполноте не останавливают импорт; повреждённый XML или отсутствие GUID останавливают.
6. Отправьте изменения `tsakorpus/corpus/`, `tsakorpus/conf/`, `tsakorpus/reports/` и `data/corpus-status.json` на GitHub (Commit + Push в GitHub Desktop). Не публикуйте исходные XML.
7. Дождитесь успешного **Corpus checks** и обновите сервер по инструкции ниже.

Локальный импорт сам по себе не обновляет серверный индекс.

Идентичность определяется GUID FieldWorks, а не именем файла. Тот же GUID заменяет документ целиком, другие тексты сохраняются. Две версии одного GUID в одной операции отклоняются. Новый GUID означает новый текст. Отсутствующие в выгрузке тексты не удаляются.

Вместо диалога:

```powershell
python tools/import_flex.py "C:\путь\Новый текст.xml" "C:\путь\Исправленный текст.xml"
```

Намеренное удаление: удалить соответствующие JSON из `tsakorpus/corpus/kusur` и `tsakorpus/reports`, пересчитать сводку, опубликовать и переиндексировать:

```powershell
python -c "from tools.import_flex import regenerate, ROOT; regenerate(ROOT)"
```

## Правила переноса

Сохраняются словоформы, морфемы, русские глоссы, части речи, свободный перевод и выравнивание. `lex` берётся из `cf` основы (Lex. Entries), иначе из самой основы. Это не гарантирует словарную лемматизацию; сложные основы объединяются через пробел и требуют проверки.

Часть речи слова имеет приоритет, часть речи основы дополнительно хранится в `stem_pos`. Несовпадения отражаются в отчёте без исправлений. Аффиксальные пометы (`PL`, `APUD`, `OBL(GEN)`) сохраняются буквально в категории `gloss_tag`. Сложные глоссы не расщепляются; невыраженные категории не восстанавливаются. Пунктуация не увеличивает расстояние между словами. Пробелы транскрипции восстанавливаются из токенов и требуют выборочного контроля.

## Размещение

Предварительный ориентир для малого корпуса: Linux x86-64, Docker Engine и Compose v2, около 4 ГБ памяти и запас диска. Это не нагрузочный тест. Нужны SSH, домен/поддомен с DNS на сервер и порты 80/443. Основной сайт остаётся на GitHub Pages.

Зафиксированы Tsakorpus `87bc1c6870e2ca367f98a10acb350b9df05154a3`, Elasticsearch `9.1.10`, Python 3.12. Зависимости: `deploy/requirements.txt`. Перед публичным запуском проверьте актуальные исправления безопасности; обновления версий должны проходить тест поиска.

```sh
git clone https://github.com/lillilek/kusur.git
cd kusur
cp deploy/.env.example deploy/.env
python3 -c "import secrets; print(secrets.token_hex(32))"
```

В `deploy/.env` задайте случайный `TSAKORPUS_SECRET_KEY` и реальный `CORPUS_DOMAIN`. Ключ не публикуйте. Для HTTPS оставьте `COOKIE_SECURE=true`.

```sh
sudo sysctl -w vm.max_map_count=262144
sh deploy/update.sh
cd deploy
docker compose --profile public up -d proxy
```

Администратор должен сохранить `vm.max_map_count` в `/etc/sysctl.d/` для перезапуска сервера. Caddy получает HTTPS-сертификат. Elasticsearch не публикует порт наружу; приложение слушает loopback; конфигуратор Tsakorpus отключён. Пароль Elasticsearch отключён только внутри выделенной Docker-сети: не публикуйте порт 9200.

Проверьте `https://ВАШ-ДОМЕН/search` и `/healthz`. Только затем укажите в `data/corpus-endpoint.json`:

```json
{"search_url": "https://ВАШ-ДОМЕН/search"}
```

После публикации файла появится кнопка поиска. Страница проверяет корректность адреса, но не доступность внешнего сервера из браузера.

Локальная проба: `COOKIE_SECURE=false`, не запускать `proxy`, открыть `http://127.0.0.1:7342/search`. На Windows нужен Docker Desktop с Linux-контейнерами, он не устанавливается автоматически.

## Обновление сервера

После отправки новых данных, из папки репозитория на сервере:

```sh
git pull --ff-only
sh deploy/update.sh
```

Образ пересобирается, поиск останавливается, индекс `kusur` заменяется и проверяется по числу документов/сегментов, приложение перезапускается. При ошибке скрипт останавливается. Volume не удаляется. Переиндексация не атомарна: при ошибке простой продолжается до исправления или отката.

Откат: разверните предыдущую проверенную версию в отдельной рабочей копии и повторите запуск с тем же Compose project `kusur-corpus`; индекс восстановится из JSON. `.private` резервируется отдельно. Автоматический SSH-деплой не настроен, поскольку сервера нет.

## Проблемы и следующие этапы

1. **Сервер и адрес:** отсутствуют, публичного поиска ещё нет.
2. **Аудио:** XML содержит локальную ссылку на WAV. Нужны медиафайл, таймкоды сегментов (например, ELAN/FLExText с выравниванием), `src_alignment` и нарезка ffmpeg. Локальный путь не публикуется.
3. **Примечания:** четыре заметки сохранены в `.private/notes`. После редакторской проверки импорт с `--include-notes` помещает их в метаданные сегментов, поле note предусмотрено в поиске. Нужны решение о публичности и показ отдельной строкой. Рабочие заметки пока не публикуются.
4. **Полнота:** 18 слов без морфем, три морфемы без глосс, пять несовпадений части речи основы и слова. Исправлять в FieldWorks и выгружать заново.
5. **Теги:** согласовать категории падежа, локализации, числа, класса, глагольных форм, сложные глоссы и нулевые показатели. Пока хранится исходная помета.
6. **Леммы:** нужны правила сложных основ, омонимов, вариантов и связи со словарём. `hn` не участвует в идентичности леммы, `variantTypes` не используется в поиске. Оригиналы сохранены.
7. **Метаданные:** заполнить подтверждённые сведения о рассказчике, жанре, времени и месте. Они не выводятся догадками из имени файла. GUID текста устойчив, номера сегментов меняются после пересегментации.
8. **Кириллица:** экспорт содержит латинскую транскрипцию под кодом `av`. Дополнительная кириллическая строка не создаётся. Нужны правила транслитерации, ударений и апострофов поиска.
9. **Будущие выгрузки:** проверены данный XML и структура phrase/word. Другие языки глосс, дополнительные переводы, новые морфемные типы и версии FLEx требуют проверки. Не все дополнительные поля переносятся; исходник архивируется.
10. **Эксплуатация:** резервные копии, мониторинг, обновления, автоматизация, устранение простоя. Для сегментов длиннее 100 слов нужно пересмотреть `max_words_in_sentence`.

## Проверки

```sh
python -m unittest discover -s tests -v
python tests/smoke_server.py http://127.0.0.1:7342
```

GitHub Actions проверяет импорт, Docker, настоящую индексацию и поиск по словоформе, лемме, глоссе, части речи, переводу и отсутствующему слову. Контрольные запросы относятся к первому тексту; при его удалении измените smoke-тест.
