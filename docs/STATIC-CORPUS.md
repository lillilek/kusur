# Статический кусурский корпус

Словарь, корпус, глоссы и прежняя выгрузка текстов работают из корня репозитория на GitHub Pages. Размещение и адрес сайта не меняются. Исходные XML и локальные заметки не отправляются на GitHub.

## Быстрое обновление

1. Поместите **полный текущий набор** экспортов FieldWorks в `.private/texts/`. Сейчас это один `kusurtexts.xml` с двумя текстами. Поддерживаются `.xml` и `.flextext`; файлов может быть несколько. Заменяйте старый экспорт актуальным, не складывайте в эту папку архивные копии.
2. Запустите `UPDATE-CORPUS.cmd` или из корня репозитория:

```powershell
python -X utf8 tools/build_static_corpus.py
```

3. Проверьте `reports/corpus-import.json` и `reports/corpus-unresolved.csv`. Первый содержит показатели по каждому файлу и уникальному корпусу; второй — леммы для ручного сопоставления. Отчёт также выводится в терминал.
4. Запустите `OPEN-STATIC-CORPUS.cmd` или `python -X utf8 tools/preview_static.py`. Откройте http://127.0.0.1:8767/corpus.html. Этот просмотр не использует Docker и закрывает доступ к `.private`. Остановить — Ctrl+C.
5. Для обновления данных отправьте через обычный Commit + Push в GitHub Desktop изменённые `data/Kusur_dict.csv`, `data/static-corpus.json`, `data/glossary.csv`, `data/corpus-links.csv` и `reports/`. При первом обновлении также отправьте `corpus.html`, `glossary.html`, изменения `index.html`, `texts.html`, `assets/`, `tools/build_static_corpus.py`, `tools/preview_static.py`, инструкции, тесты и команды запуска. Не включайте посторонние незавершённые изменения. GitHub Pages публикует корень существующей ветки обычным способом.

`.private/` уже исключена из Git. Не добавляйте её принудительно. Публичные отчёты содержат имена экспортов, языковые метки, статистику и леммы; XML, локальные медиа-пути и рабочие заметки в них не копируются.

## Полная пересборка и ошибки

Каждая сборка заново читает весь набор файлов. Отсутствующие в текущих экспортах тексты и примеры исчезают; исправления заменяют старые данные. После первой успешной сборки `.private/texts/inputs.json` запоминает имена ожидаемых файлов. Если файл случайно пропал, сборка останавливается. При намеренной смене набора или переименовании файлов запустите `python -X utf8 tools/build_static_corpus.py --refresh-inputs`.

Для отдельной проверки можно явно передать полный список файлов:

```powershell
python -X utf8 tools/build_static_corpus.py .private/texts/one.xml .private/texts/two.flextext
```

Явно переданный список — весь корпус, а не добавка. Этот режим не изменяет список ожидаемых файлов. Каждый указанный файл должен существовать. Формат, GUID, содержимое, словарь и ручные таблицы проверяются до записи результатов. При ошибке экспорта последняя сборка сохраняется. Обычная ошибка записи откатывает заменённые файлы; внезапное выключение компьютера между файловыми операциями не является гарантированно атомарным — повторите сборку. Файл корпуса переключается последним и содержит сразу все тексты, связи и глоссарий.

## Идентичность и постоянные ссылки

- Текст определяется GUID FieldWorks. Имя файла и порядок аргументов не влияют на ссылки. Порядок текстов стабилен по GUID.
- Два одинаковых текста одного GUID включаются один раз. Сравнивается структура XML без форматных пробелов, порядка атрибутов и дат экспорта. Разное содержимое одного GUID останавливает сборку с именами обоих файлов.
- У предложения используется GUID предложения, если экспорт его содержит. Иначе — GUID текста и исходный `segnum`/`ref`. В текущем экспорте GUID предложений отсутствуют, номера есть. Повтор номера внутри текста или отсутствие и GUID, и номера — ошибка. Пересборка, переименование файла и исправление текста при сохранении номера сохраняют ссылку. Перенумерация предложений в FieldWorks может изменить ссылки: без GUID предложения гарантировать их сохранность нельзя.
- У словаря добавлен постоянный столбец `entry_id`. **Сохраняйте этот столбец и его значения** при правке и повторном экспорте таблицы. Порядок строк и изменения других полей не влияют на ID. Для новой записи пустой ID будет заполнен сборщиком; повтор ID — ошибка. Удаление столбца лишает сборку возможности гарантировать старые ссылки.

## Разметка и названия

Читаются все `interlinear-text`, структуры `phrases/phrase` и встречающаяся в реальном XML `phrases/word`. Вложенный текст item, включая `run`, сохраняется. Приоритет названия — `av`, затем `kus`, затем `ru`. Удаляется только начальная служебная нумерация вида `01. ` или `1) `. Сейчас оба названия — служебные `kus_2026_…`; красивого кусурского названия в экспорте нет. Задайте его в FieldWorks и выгрузите снова.

Словоформы и морфемы берутся из `txt`, леммы из `cf`, глоссы из `gls`, части речи из `pos` и `msa`. Для перевода приоритет `ru`; при его отсутствии текст с кириллицей распознаётся как русский даже под `en` и отражается в отчёте. Латинский английский перевод автоматически русским не объявляется. Альтернативные элементы `morphemes` сохраняются раздельно. Многоязычные дубли item внутри одного разбора выбираются по языковому приоритету, а не превращаются в новые разборы.

Формы морфем показываются буквально. Незаписанные дефисы и `=` не восстанавливаются по типу морфемы. На строку глосс переносятся только крайние границы, явно записанные в формах. Отсутствующая форма/глосса — `?`; отсутствие морфемного разбора также видно. Неизвестные грамматические обозначения не расшифровываются автоматически.

В текущем сайте нет отдельного набора правил кириллица ↔ латиница. Новая версия не вводит догадочную транслитерацию; использует готовые написания словаря. Нормализация поиска переиспользует `assets/search.js`: ударения, палочка, русское ё, опциональная диакритика; й сохраняется. Подсветка вычисляется по карте позиций исходной NFC-строки. В регулярном поиске синтаксис выражения не нормализуется.

## Связи со словарём

Кандидаты берутся из точного нормализованного совпадения с латинским/кириллическим заголовком, вариантами и полем форм (разделители — запятая, точка с запятой, перенос строки). Для единственной основы дополнительно проверяется словоформа. Автоматическая связь требует согласованной части речи, совпадения с отдельным русским значением и единственного кандидата. Только похожего написания или общего перевода недостаточно. При наличии номера омонима `hn` нужна ручная проверка. Составные основы сопоставляются по отдельным морфемам, без выдуманной общей леммы.

`reports/corpus-unresolved.csv` пересоздаётся. Не вносите правки в этот отчёт. Подтверждённые решения добавляйте в **`data/corpus-links.csv`**:

```csv
lemma,pos,gloss,homograph,entry_id
```

Скопируйте первые четыре поля из отчёта, затем впишите `entry_id` из словаря. Пустой `entry_id` — явное решение не связывать. Ручное решение имеет приоритет и сохраняется между сборками. Несуществующий ID или противоречивые строки вызывают ошибку. Автоматические связи лучше выборочно проверить перед публикацией; они не заменяют лексикографическую редактуру.

В статье словаря примеры раскрываются **новой строкой на все пять колонок**: до трёх примеров и ссылка на полную выдачу. Из леммы в разборе можно перейти к статье. Фильтр статьи в корпусе сохраняется в URL.

## Глоссарий и поиск

Редактируйте `data/glossary.csv` в UTF-8, столбцы **глосса,пояснение**. После правки запускайте сборку. Новые обозначения, начинающиеся с латинской заглавной буквы или цифры, добавляются без пояснения; существующие пояснения и старые строки сохраняются. Сложная глосса остаётся целой: `OBL(GEN)` не расщепляется догадочно. Лексические русские глоссы доступны в поиске корпуса, но не включаются в список грамматических обозначений.

Простой поиск — по словоформам, строкам, леммам, морфемам, глоссам, частям речи и переводам. Расширенные условия выполняются на одном слове и одном альтернативном разборе; последовательность глосс допускает `*`, второй элемент — порядок, расстояние без пунктуации, обязательность/факультативность/исключение. Для простого поиска есть регулярные выражения и точная целая глосса; в расширенных полях используются целые значения с `|` и `!`.

Поиск и вычисление подсветки идут в Web Worker. Долгий запрос прекращается через 3 секунды, следующий запрос запускается в новом обработчике. URL хранит поля, запрос и параметры. Подборка хранится в localStorage этого браузера; её содержимое не пересылается ссылкой. Есть интерлинеар, KWIC, переключение уровней, копирование, TSV и переход к полному тексту. TSV экспортирует всю выдачу, а не только показанную порцию.

## Проверки и происхождение компонентов

```powershell
python -X utf8 -m unittest discover -s tests -v
node tests/static-search.cjs
node tests/static-ui.cjs
```

Для последнего теста нужен Playwright и браузер Edge (или `BROWSER_CHANNEL=chrome`). Путь к установленному модулю при необходимости задаётся `PLAYWRIGHT_MODULE`. Тест проверяет четыре страницы в ширинах 1280/375, подсветку, ссылки, подборку, копирование, TSV и восстановление после ошибочной/зависшей регулярки. Скриншоты сохраняются в `.private/`.

Интерлинеар, последовательности глосс, KWIC, подборка, клавиатура и параметры URL адаптированы из [tools/reader.html](https://github.com/lillilek/itelmen/blob/main/tools/reader.html) и [tools/site-ui.js](https://github.com/lillilek/itelmen/blob/main/tools/site-ui.js), изучена версия дерева `edb54e988c4936e4a2523868f84a20e0da777879`. Импорт и сопоставление переработаны под кусурские поля, один/несколько экспортов, альтернативные разборы и сохранение рабочей сборки. Ительменские правила транслитерации и автоматического добавления морфемных границ не перенесены.
