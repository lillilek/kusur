# Кусурский диалект: словарь и тексты

Готовый статический сайт для GitHub Pages. Сборка, установка пакетов и серверная база данных не нужны.

## Как опубликовать

1. Распакуйте ZIP. Откройте находящуюся внутри папку `kusur-site`.
2. Войдите в GitHub. Нажмите **+ → New repository**, назовите репозиторий, например `kusur`, выберите **Public** и нажмите **Create repository**. Для бесплатного размещения используйте публичный репозиторий: опубликованные материалы будут доступны всем.
3. Нажмите **uploading an existing file** (в уже созданном репозитории: **Add file → Upload files**).
4. Перетащите **содержимое** папки `kusur-site`, включая папки `assets` и `data`. Не загружайте сам ZIP. `index.html` должен лежать непосредственно в корне репозитория, а не внутри дополнительной папки `kusur-site`.
5. Нажмите **Commit changes**. Файлы должны оказаться в ветке `main`.
6. Откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Source → Deploy from a branch**, затем **Branch → main**, папку **/(root)** и нажмите **Save**.
7. Дождитесь завершения публикации. Адрес появится в **Settings → Pages**: обычно `https://ВАШ-ЛОГИН.github.io/kusur/`. Ход публикации можно посмотреть во вкладке **Actions**.

Если показывается 404, дождитесь окончания публикации, проверьте ветку и расположение `index.html`, затем откройте именно адрес из Settings → Pages.

Файл `.nojekyll` отключает ненужную обработку Jekyll. Он включён в архив; если ваш файловый менеджер скрывает файлы с точкой, включите их отображение. При необходимости создайте пустой `.nojekyll` через Add file → Create new file.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Как обновлять словарь — без изменения кода

Сайт при открытии загружает `data/Kusur_dict.csv` и заново рассчитывает поиск и количество записей. Отдельного встроенного дубликата словаря нет.

1. Экспортируйте новую таблицу в **CSV UTF-8 с разделителем запятая**. Например, в Google Sheets: Файл → Скачать → Значения, разделённые запятыми (.csv). Сохраните названия столбцов. Их порядок может меняться.
2. Назовите файл строго `Kusur_dict.csv`, даже если скачанный файл называется `Kusur_dict_updated.csv`.
3. В репозитории GitHub откройте папку **data**.
4. Выберите **Add file → Upload files** и загрузите новый `Kusur_dict.csv`. Это заменит старый файл по тому же пути. Не загружайте новую таблицу в корень и не создавайте вложенную папку data/data.
5. Нажмите **Commit changes** (непосредственно в `main`). GitHub Pages опубликует обновление автоматически.
6. После завершения публикации перезагрузите сайт. При необходимости нажмите **Ctrl+F5**. Счётчик покажет актуальное количество записей.

Можно добавлять и удалять строки, менять значения и порядок записей. Повторяющиеся заголовочные слова остаются отдельными записями. Пустые поля не показываются. Не переименовывайте используемые столбцы:

`pos`, `cyrillic orthography`, `latin orthography`, `variant`, `glossing label`, `forms`, `comment`, `meaning_1_rus`, `meaning_1_eng`, `meaning_2_rus`, `meaning_2_eng`, `sources`, `в лит.варианте`, `происхождение`, `example_1_cyr`, `example_1_rus`, `example_2_cyr`, `example_2_rus`.

Дополнительные исходные столбцы сохранены в CSV, но не выводятся в пяти визуальных группах. Кавычки, запятые и переносы строк внутри ячеек поддерживаются. Используйте экспорт таблицы: не собирайте CSV вручную соединением строк через запятую.

Если ошиблись, предыдущую версию CSV можно найти через историю файла в GitHub и загрузить снова.

## Как обновлять тексты

Раздел `texts.html` содержит все данные текстов внутри HTML. Новую совместимую выгрузку можно загрузить под именем `texts.html` вместо старой. Поиск новой выгрузки сохранится; чтобы сохранить переход к словарю, добавьте сразу после открывающего `<header>`:

```html
<nav><a href="index.html">Словарь</a> · <a href="texts.html">Тексты</a></nav>
```

Аудиозаписи не входят в приложенную выгрузку и в этот сайт.

## Просмотр на компьютере

Опубликованный сайт открывается обычной ссылкой. Для локальной проверки словаря нужен HTTP-сервер, потому что браузеры ограничивают чтение CSV через `file://`.

Если установлен Python, откройте терминал в папке `kusur-site` и выполните:

```text
python -m http.server 8000
```

На Windows можно использовать `py -m http.server 8000`. Откройте http://localhost:8000 . Для остановки нажмите Ctrl+C.

## Файлы

- `index.html` — словарь.
- `texts.html` — тексты с поиском и фильтром по файлу.
- `data/Kusur_dict.csv` — единственный источник данных словаря; заменяйте его для обновления.
- `assets/search.js` — CSV-парсер и поиск.
- `assets/app.js` — вывод словарных записей.
- `assets/style.css` — оформление словаря и мобильная версия.
- `.nojekyll` — настройка статической публикации.
- `CHECKS.md` — выполненные проверки.

Поиск охватывает весь CSV. Для плавного ввода выводятся порции по 150 записей: нажимайте «Показать ещё» для продолжения. При пустом запросе доступны все записи в исходном порядке. Шрифты берутся с устройства пользователя; внешние сервисы, CDN и аналитика не используются.
